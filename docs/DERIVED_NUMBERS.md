## A conservative finite derived bound

Every accepted source numerator/denominator has magnitude below 10^128. A fixed item weight has denominator below 500 × 10^128 < 10^131. Across both endpoints, each item uses at most four effective score denominators (actual singletons replace boxes). A common denominator for all 500 items is therefore less than (10^(131+4×128))^500 = 10^321500. Nonnegative item weights sum to one, so endpoint magnitude is below 2×10^128; width and non-overlapping acquisition reduction are below 4×10^128. A derived numerator consequently has at most 321629 digits. Plan cost has at most 32 source-price denominators and magnitude below 32×10^128, yielding a much smaller bound.

The codec conservatively allows **322000 digits per integer component**, or **644002 characters** including sign and fraction separator. Inputs above that finite bound are refused before whole-number parsing. Within the bound, canonicality plus the checker's manifest-specific arithmetic rejects fabricated values; a syntactically bounded value is not certified merely because it parses. This bound supports all mathematically legal source inputs under existing item/action caps; it is not a population-inference or arbitrary-bigint guarantee. Exact big-denominator arithmetic and chunk conversion cost CPU and memory; no wall-clock deadline is promised. Existing 4 MiB CLI JSON file and search-node caps remain. CLI exports also refuse a fully formatted UTF-8 payload above 4 MiB before writing, so oversized imported local metadata cannot create a successful but unreadable export.
