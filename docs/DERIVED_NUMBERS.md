## Separate ingress and computed output

Manifest scores/costs/weights, observation scores and policy margins/budgets still accept at most 128 characters per source literal. JSON floats remain refused. Derived certificate values use canonical ASCII reduced fractions or integers: no decimals, leading zeros, negative zero, redundant `/1` or unreduced fractions. Envelope endpoints/width, contributions/weights/witnesses, selected action costs/reductions, total plan costs/reductions/remaining widths and UNKNOWN upper bounds all use this derived codec. Checkers retain their independent arithmetic, witness feasibility and status/constraint checks.

Large source decimals can normalize to fractions longer than 128 characters even before any sum. Source persistence therefore emits the reduced fraction when it fits; otherwise it emits the shortest exact terminating decimal. That decimal remains within the original source cap. Manifest/state exports and normalized policy fields remain valid source inputs. This does not enlarge source ingestion or relabel generated values as actual observations.

The integer formatter divides into base-10^9 chunks; the parser assembles at most 9 decimal digits per conversion. Neither calls `sys.set_int_max_str_digits`, changes process settings, nor delegates a whole large decimal integer to `int`/`str`. The default Python 4300-digit conversion policy remains intact, including for unrelated application code. Oversized unquoted JSON source integers get a typed refusal before Python's whole-integer parser runs.

## A conservative finite derived bound

Every accepted source numerator/denominator has magnitude below 10^128. A fixed item weight has denominator below 500 × 10^128 < 10^131. Across both endpoints, each item uses at most four effective score denominators (actual singletons replace boxes). A common denominator for all 500 items is therefore less than (10^(131+4×128))^500 = 10^321500. Nonnegative item weights sum to one, so endpoint magnitude is below 2×10^128; width and non-overlapping acquisition reduction are below 4×10^128. A derived numerator consequently has at most 321629 digits. Plan cost has at most 32 source-price denominators and magnitude below 32×10^128, yielding a much smaller bound.

The codec conservatively allows **322000 digits per integer component**, or **644002 characters** including sign and fraction separator. Inputs above that finite bound are refused before whole-number parsing. Within the bound, canonicality plus the checker's manifest-specific arithmetic rejects fabricated values; a syntactically bounded value is not certified merely because it parses. This bound supports all mathematically legal source inputs under existing item/action caps; it is not a population-inference or arbitrary-bigint guarantee. Exact big-denominator arithmetic and chunk conversion cost CPU and memory; no wall-clock deadline is promised. Existing 4 MiB CLI JSON file and search-node caps remain.
