# Supported format, mathematics and operations

`version:1`, `kind:independent_boxes`, `identity:{manifest,old_model,new_model,scorer}`, `strata:{name:weight}`, `items:[{id,stratum,old:{low,high,cost},new:{low,high,cost},bundle_cost?}]`. Unknown fields are refused, including coupled constraints. IDs use ASCII letters, digits, `_`, `.`, `-` (1–100 characters); colon belongs to action syntax. Weights must be nonnegative and sum exactly to one. All declared strata have at least one paired sample, even when their weight is zero.

An item in stratum s has fixed weight w_i = W_s / N_s, where N_s counts **all** originally declared members. No observation removes members or changes N_s. Both model arms have independent score boxes; an actual score becomes a singleton without changing the declared manifest. A singleton declared box does not imply an actual observation or completed-pair coverage.

For full finite difference D = Σ_i w_i(new_i − old_i), the tight lower endpoint is Σ_i w_i(newLow_i − oldHigh_i), and upper endpoint is Σ_i w_i(newHigh_i − oldLow_i). Nonnegative weights and independent boxes let all minimizing/maximizing arm choices coexist. Thus every endpoint witness is legal and attains its endpoint. Zero weights contribute exactly zero to both bounds and acquisition benefit. Range scores may lie outside [0,1] when the scorer declares them. The model rejects cross-score consistency, coupled rubrics, correlated constraints and stochastic population claims.

At release margin m: PASS iff lower ≥ m, FAIL iff upper < m, otherwise INCONCLUSIVE. This convention means equality passes. The policy is explicit and separate from the mathematical range. Missingness can be arbitrary and can leave bounds uninformative forever.

Actual imports use `kind:actual_observations`, the manifest digest and exact identity, and rows `{event_id,item,arm,value,source,kind:actual}`. Conflicting event IDs or immutable cell scores are refused; identical event repeats are idempotent. Multiple event IDs confirming the same cell/value are retained. Source labels are local declarations, not authenticated provenance. `completion_certificate` and its constructed witness rows are a different format and are refused as imports. The SHA-256 digest binds canonical semantic manifest content, not authenticity or timestamp ordering.

State records store actual observations separately from frozen acquisition-plan receipts. Each frozen plan names the manifest digest and exact prior state digest. Import with that plan must fulfill exactly its selected cells. The planner has no future-score input and never opens the observation file. Caller-controlled JSON cannot prove that a caller did not privately view future values; the demonstrated workflow enforces the order of its own file creation and CLI invocations.

Receipt history is capped at 1000 records. Every frozen-plan import, including a legitimate empty collection, consumes one receipt. At the cap it refuses with a typed error before creating an output state; CLI input/existing output files remain unchanged. A non-frozen empty or identical-event import adds no receipt and remains idempotent at the cap. Duplicate caller-supplied receipt declarations count toward the cap; they are not authenticated or treated as proof of a unique collection. Reusing a stale frozen plan refuses independently through the prior-state binding.

## Collection problem and complexity

Each missing single arm's reduction is w_i × (declaredHigh − declaredLow), independently of the future value. Its price is its own declared cost. `item:both` exists only when both arms are missing and an explicit `bundle_cost` is declared; it consumes both cells and has their summed reduction. Selected actions cannot overlap cells. Pins use exact action IDs. `coverage:{stratum:min}` requires at least that many actually completed paired samples after acquisition; existing actual observations count, deterministic but unobserved boxes do not. Coverage counts may include zero-weight items, but their benefit stays zero.

The objective maximizes total reduction, then minimizes cost, then lexically compares sorted selected action IDs. Bounded depth-first subset search supports at most 32 actions. The search-node budget is a hard limit; exhausted search returns UNKNOWN with an optional feasible incumbent and a valid conservative reduction upper bound (the current total width). It never labels an incumbent OPTIMAL. No feasible incumbent on exhaustion is different from proven infeasibility. Exhaustive completion returns OPTIMAL or INFEASIBLE. Complexity is O(2^A × (A+N)) worst case, with O(A+N) stack/state storage. Envelope computation and witness checking are O(N). This scope fits expensive small follow-up batches, not millions of acquisition combinations.

`check` independently derives action prices/benefits, validates overlaps, budget, pins and coverage. By default it verifies feasibility/accounting, **not** the OPTIMAL/INFEASIBLE search claim. `--prove-optimal` enumerates all subsets up to 20 actions using a separate implementation and checks optimality, tie breaking and infeasibility; UNKNOWN stays UNKNOWN even if the oracle can solve the tiny case. Tests also independently enumerate box corners (one-sided missing and nonuniform strata). Enumerating corners suffices for a linear expression over a box; it is not a statistical simulator.

## Resource and file limits

At most 500 items, 100 strata, 1000 observation records per input batch/state, 128 characters per exact **source** numeric literal, 4 MiB per CLI JSON file and 1,000,000 planner nodes. Derived certificate fractions have separate finite canonical limits: 322000 decimal digits per integer component, 644002 characters per number. [The derivation and conversion protocol](DERIVED_NUMBERS.md) explain why all legal source results fit and how large integer components avoid process-wide digit-setting changes. Source decimals remain within the 128-character bound when states/manifests are persisted. Finite declared numbers may still be expensive if their denominators differ greatly; no wall-clock deadline is promised. The CLI bounds both read files and fully formatted UTF-8 output to 4 MiB. Oversized output refuses before stdout, directory creation or replacement; this also applies to valid but oversized caller-supplied receipt metadata. The CLI writes atomic replacement JSON locally, returns 0 on successful computation (including INCONCLUSIVE/UNKNOWN/INFEASIBLE) and 2 on invalid/unsupported input or I/O failure. It does not contact a model, spend acquisition costs, alter a deployment or collect observations itself. Costs are caller-defined units, not monetary evidence.
